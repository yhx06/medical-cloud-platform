## 本轮修复及回归证据

| 问题 | 修复与验证 |
| --- | --- |
| 续跑文件接受不可能的日期、时段和字符串布尔值 | 五个错误输入先复现，再修复；现在发送 HTTP 请求前拒绝，并检查已取消检查点必须带预约 ID |
| 角色越权误返回 401 | 四个真实服务守卫测试先得到错误的 401；改为 403，并保留未认证返回 401；真实接口再次通过 |
| 当天已开始号源仍可查询与预约 | 目录和锁内预约均按上海时间检查开诊截止；当前日零点号源的回归先失败后通过，未来号源仍可用 |
| 医生调科后缓存旧号源仍可预约 | 在科室→医生→号源锁序下重验科室状态及医生当前关联；正常调科流程的回归先失败后通过 |
| MySQL 旧快照漏掉刚提交的预约 | 在临时 MySQL 实例的 REPEATABLE READ 下，先建立管理员快照，再提交患者预约，最后尝试撤回号源。原逻辑错误放行，修复后锁内当前读拒绝撤回，预约保留且号源仍为 PUBLISHED |

预约截止选择开诊开始时间，与现有取消截止一致；科室共享锁位于医生锁之前，保持所有路径的号源锁早于预约锁。测试夹具补齐真实模型要求的医生科室关联。
