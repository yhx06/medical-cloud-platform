# 医疗云课程版：医院启停与统计看板设计

日期：2026-10-03。阶段：功能范围已获同意，本书面设计待用户审阅；不是已实现功能说明。

## 1. 目标、依据与范围

在已完成 P0 业务闭环和预约目录交互的课程版上，补齐医院启停管理与统计展示，供期末演示和报告使用。依据需求分析的 `FR-TEN-05`、`FR-STAT-01`、`FR-STAT-02`、`AT-07`：平台可启停医院；停用禁止新业务，但授权历史查询保留；医院查看本院统计；平台只看跨医院脱敏汇总，不看患者身份或诊疗正文。现有至少两家虚构医院继续满足 `FR-TEN-01`。

本轮包括：

- 平台管理员查看已有医院列表、启用或停用医院，不删除医院及关联业务数据。
- 医院管理员查看本院预约、诊疗、订单金额及按日趋势，日期口径可追溯。
- 平台管理员查看医院状态数量、跨医院汇总、分医院汇总和按日趋势。
- 分离账号认证与医院业务状态，停用医院仍支持原有授权范围的历史查询。
- 补齐所有受医院状态影响的写操作检查、真实 MySQL 并发验证及门户验收。

不包括新建医院、创建医院管理员、平台停用账号、附件/对象存储、持久化审计、真实支付、退款、真实诊疗、AI、统计导出或监控大屏。账号数量不是本轮指标，避免将无创建时间的账号误计为区间新增账号。后续附件和审计另行设计。

只修改 `course/` 及相关说明，不迁回原 `backend/` Java 21/Spring 或 `frontend/` Vue 技术栈。IaaS 的 70 台服务器仍仅为 PowerDesigner 逻辑模型，不实际启动。

## 2. 技术方案与边界

选择在现有 `contract → paas → portal` 三模块内增加纵向业务切片：Java 8；Tomcat 9 的 Servlet/JSP 展示 SaaS 门户；WildFly 10 的 JAX-RS/EJB 承担接口、授权、事务；JPA 经 JNDI 数据源访问 MySQL。保留课程的 `CloudServiceFactory`、角色门面及架构说明。

另两个可选方案不采用：只在 JSP 计算现有列表会受 100/200 条截断影响，且不能保护绕过页面的写请求；另建统计服务或引入 Spring/图表平台会增加部署和课程架构偏差。本方案直接在数据库聚合，门户只呈现安全 DTO。

组件职责：

- `contract`：医院安全列表、启停请求、当前医院业务状态、统计范围、统计汇总及每日趋势 DTO。不得序列化账号实体、病历实体或任意查询结果。
- `paas/tenant`：平台医院管理 EJB，以及可复用的医院读权限/写状态策略。读权限只验证合法身份和归属；写策略还要锁定并确认医院启用。
- `paas/statistics`：严格日期范围解析、角色和租户边界、数据库聚合、空值归一化及补齐零值日期。查询实现与指标定义分离。
- JAX-RS：新增平台管理、医院状态和统计资源；复用现有 Bearer 认证和错误体。业务规则不放在 JSP。
- `portal`：平台医院表格与统计、医院统计区、只读状态提示；Servlet 通过 `PaasClient` 调用 PaaS，不直连数据库。新页面装配逻辑按医院管理/统计拆分为小单元，避免继续将所有流程堆在 `PortalServlet`。

现有业务接口路径、请求体和成功字段保持兼容。医院停用后受保护写请求变为冲突，是本轮明确的行为变更。

## 3. 身份、医院状态与只读规则

### 3.1 认证与授权

`AuthService` 每次登录或校验令牌仍验证账号存在、`ACTIVE`、合法角色。医生/医院管理员必须有存在的所属医院，数据库账号归属须与用于授权的主体一致；所属医院为 `DISABLED` 不再单独导致认证失败。未知医院状态不能获得历史读权限，不能因移除原 `tenantActive` 而放开无归属身份。

医院启停不修改任何 `Account.status`。独立停用的账号仍不能登录或用旧令牌查询；重新启用医院也不能恢复该账号。旧的有效令牌不缓存医院状态：每次写请求在业务事务内检查数据库当前医院状态，历史读请求仍验证账号和原归属。过期令牌按原规则拒绝。

平台不能调用患者、医生、医院管理员的明细接口。医院停用不扩大医院管理员的临床权限：其历史只读限于原有本院科室、医生、排班、订单，以及新统计。医生只读本人本院预约和本人病历；患者只读本人预约、病历和账单。

### 3.2 停用边界（本设计提出的具体规则）

采用完整业务冻结，而非自动清理或后台继续写入。平台可以停用仍有未完成预约或未付账单的医院；页面操作前明确告知影响，不因这些记录拒绝医院停用。停用不取消预约、不撤回号源、不生成病历、不改变金额或支付状态。

| 操作 | 医院 ACTIVE | 医院 DISABLED |
| --- | --- | --- |
| 合法启用账号登录、授权历史查询 | 按原权限允许 | 按原权限允许 |
| 公共医院/科室/医生目录与可预约号源 | 按原公开规则允许 | 不展示该医院的可办理资源 |
| 新预约 | 按原规则允许 | 拒绝 |
| 取消预约 | 按原状态和截止时间允许 | 拒绝；保留原状态 |
| 医生开始/完成接诊 | 按原规则允许 | 拒绝；不生成病历或订单 |
| 患者模拟缴费，包括重复提交已付订单 | 按原幂等规则允许 | 拒绝；查询已付结果仍允许 |
| 科室、医生、号源新增或修改，包括停用/撤回 | 按原规则允许 | 拒绝 |
| 本院统计及平台统计 | 按角色范围允许 | 历史继续纳入统计 |
| 平台重新启用医院 | 可重复提交 | 允许；不改变下属资源状态 |

取消和支付虽关联旧业务，也属于写操作，停用期间一并冻结。此规则以课堂可解释和权限一致为目标，不适用于真实医院应急停用。未完成预约和未付账单保留待处理状态；重新启用后仍按原状态机、时间截止和资源状态校验，不保证过期预约可继续取消，不自动恢复独立停用的医生/科室或已撤回号源。患者注册不归属医院，不受某医院停用影响。

### 3.3 并发与启停幂等

启停事务先验证平台管理员身份，再对目标医院取 `PESSIMISTIC_WRITE` 并刷新状态；只更新该行的状态字段。请求携带目标 `status` 和页面读取的 `expectedStatus`，均只接受 `ACTIVE`/`DISABLED`。当前状态已等于目标时返回成功，不产生额外业务副作用；否则当前状态必须等于 `expectedStatus`，不一致返回 409，防止过期表单覆盖另一管理员的变更。

所有本院业务写事务在锁定其他业务行之前，对目标医院取得 `PESSIMISTIC_READ` 并刷新，确认 `ACTIVE`；锁保持到事务提交。沿用原业务锁顺序并加上医院前缀：`医院 → 科室（如需要）→ 医生（如需要）→ 号源（如需要）→ 预约（如需要）→ 订单（如需要）`。多科室/多医生继续按 ID 排序。身份校验和定位目标可先进行非锁定读取，但取锁后必须重验目标归属，不能依赖旧快照。

覆盖预约、取消、开始/完成接诊、支付、科室维护、医生维护、号源维护全部写入口。禁止某服务先持有医生/号源/订单写锁，再回头获取医院锁。租户读取策略必须显式区分只读与写事务，不能靠删除原启用检查来实现。

若业务先取得医院读锁，其事务可先完成，平台停用等待该事务释放后提交；若停用先提交，后续业务写必须失败。停用接口成功后，不能再提交绕过此边界的新业务变更。锁超时/死锁须回滚并映射为可重试冲突，不泄露 SQL；不盲目重试非幂等创建。

## 4. 统计口径

### 4.1 范围与时间

新统计接口使用 `from`、`to`，严格接受真实有效的 `yyyy-MM-dd` 日期，首尾日期均包含。参数去除首尾空白后，空值视为未提供；两者同时缺省时为上海当天及前 29 天；只提供一个日期视为 400；起日晚于止日、区间超过 366 个自然日或不可构造次日上界均为 400。允许选择过去或未来日期，没有数据返回零，不伪造数据。

预约以 `booked_on` 筛选，日期闭区间；其含义是预约下单日期，不是号源就诊日期。事件时间统一转换为上海时区的 `[from 当日 00:00, to 次日 00:00)`。当前 MySQL 使用上海本地 `DATETIME`，JDBC `serverTimezone=Asia/Shanghai` 和 JVM 课程时区须一致；不得把该列当 UTC 再偏移八小时。接口回传规范化起止日期、时区 `Asia/Shanghai`、生成时间，页面显示完整范围和指标说明。

### 4.2 指标定义

| 指标字段 | 精确定义 | 日期依据 |
| --- | --- | --- |
| `appointmentTotal` | 所选日期内创建的全部预约，包括后来取消的预约 | `appointment.booked_on` |
| `appointmentBooked` / `appointmentInProgress` / `appointmentCanceled` / `appointmentCompleted` | 上述预约集合按查询时当前状态分类；不是状态转换当日数量 | 同上 |
| `consultationStarted` | 有接诊开始时间的预约数，包括后来完成的预约 | `appointment.started_at` |
| `consultationCompleted` | 完成病历数，不查询病历正文 | `clinical_record.completed_at` |
| `orderGenerated` / `orderAmount` | 所选日期生成的订单数和应收金额；订单仅在接诊完成时生成，因此使用对应病历完成时间 | 同租户、同预约订单与病历关联后的 `completed_at` |
| `paidOrderCount` / `paidRevenue` | 当前 `PAID` 且实际支付时间在范围内的订单数/金额；是模拟实收，不是应收 | `payment_order.paid_at` |

预约四状态小计之和等于预约总数；重约产生新预约，取消记录不删除。`appointmentCompleted` 与 `consultationCompleted` 分别是下单群体的当前完成数和区间内完成事件数，不能互换或宣称两者必然相等。`orderAmount` 与 `paidRevenue` 亦不必相等；不同日期生成的订单可在本区间付款。

金额使用 `BigDecimal` 和数据库 `DECIMAL`，以人民币元显示两位小数，不用浮点数累加。空的 `SUM` 返回 0.00，计数返回 0。不得根据病历内容、患者去重或患者姓名推导指标。

每日趋势为区间内按升序排列的全部自然日，每天包含同一组指标并补齐零值；每个区间指标必须等于其每日值之和。分医院汇总使用相同范围和口径，包括停用医院及零业务医院；平台总数必须等于全部医院汇总之和。医院总数/启用数/停用数为查询时存量，单独标注“不受日期筛选影响”。不以现有有上限的业务列表作为统计来源。

### 4.3 旧数据与未知时间

不补造旧记录时间、不用升级时间/预约日期代替接诊或支付时间。旧预约的 `booked_on` 仍可用于预约指标，即使 `booked_at` 为空。有状态但无 `started_at` 的旧接诊、有病历但无 `completed_at` 的旧诊疗、有 `PAID` 状态但无 `paid_at` 的旧账单，不计入对应区间事件及按日趋势。

每次统计另外返回授权范围内、跨全部日期的 `legacyUnknownTime`：已开始或已完成但无开始时间的预约数、无完成时间的病历数、缺少可用关联病历完成时间的订单数/金额、已付但无支付时间的订单数/金额。页面明确称为“历史时间未知：全量补充说明，不属于所选区间”，不能加到区间合计。这些字段也只允许数值，不包含记录 ID 或个人信息。同一旧记录可能影响多项时间质量提示，不能将各提示简单相加为记录总数。

## 5. 数据访问与隐私

医院统计的租户 ID 由数据库中启用账号的归属确定，不信任请求、会话中旧的医院 ID。医院统计接口不接受 `tenantId`；即使恶意附加也不得改变范围，显式拒绝该参数。平台查询仅允许平台管理员；可以按医院汇总，但不增加预约/订单明细下钻。

数据库只投影 `COUNT`、`SUM`、日期、医院 ID/名称/状态及统计所需状态分组，不读取诊断、主诉、建议、备注、患者 ID、患者用户名、密码哈希或令牌。订单/病历关联必须同时匹配预约 ID 和租户 ID，防止不一致数据跨院串联。日期查询参数化，不能拼接用户输入 SQL。

MySQL 原生聚合可使用上海 `DATETIME` 的 `DATE(...)` 按日分组；聚合适配器封装 SQL，H2 测试不能代替真实 MySQL 的时区与隔离验证。平台总计由本次完整的分医院聚合结果计算，不能从分页医院表格求和。统计在同一 EJB/JTA 事务、经确认的 MySQL `REPEATABLE READ` 一致读快照中执行，保证当前响应的汇总/趋势/状态数量相互一致，不锁住整张业务表。验收检查实际隔离设置；条件不满足则先调整隔离课程数据源并复验，不宣称一致性已得到保证。

不引入定时物化统计、缓存或新业务表。查询随业务实时变化，页面不承诺跨刷新保持同一快照。本轮无需数据库迁移，保持 `hibernate.hbm2ddl.auto=validate`；不执行初始化脚本或修补旧时间字段。

## 6. 新接口与契约

以下路径相对现有 `/paas/api`。成功延续 `{code, message, data}`；错误延续带 `requestId` 的公共错误体。

| 方法与路径 | 返回/请求 | 权限 |
| --- | --- | --- |
| `GET /platform/tenants?page=1&size=20` | 只含医院 `id/name/status` 的分页列表、总数；名称和 ID 稳定排序，size 1–100 | 平台管理员 |
| `PUT /platform/tenants/{id}/status` | 请求 `status/expectedStatus`，返回 `id/name/status` | 平台管理员 |
| `GET /hospital/context` | 本人医院 `id/name/status/businessWritable`，不含账号实体 | 医院管理员 |
| `GET /doctor/context` | 同上，仅本人所属医院 | 医生 |
| `GET /hospital/statistics?from=&to=` | 范围、生成时间、本院状态、指标、每日趋势、旧时间提示 | 本院医院管理员 |
| `GET /platform/statistics?from=&to=` | 范围、生成时间、医院存量状态数量、全院汇总、全部分医院汇总、平台每日趋势、旧时间提示 | 平台管理员 |

公共目录仍只含原有 `id/name`，不为了只读 UI 把停用医院重新加入可预约选项。患者历史安全 DTO 增加所属医院状态和 `businessWritable`；本人账单视图增加 `businessWritable`，用来禁用取消/支付按钮。该字段只表达医院是否允许办理，按钮还须叠加原预约/订单状态及截止规则。历史详情不依赖医院仍在公共目录，目录查询失败也不能隐藏病历或账单。新增字段为加法兼容；前端不能作为写权限保障。

无令牌、过期令牌、停用账号为 401；角色不符、跨院或非本人对象为 403；非法状态/日期/分页为 400；业务冻结、过期状态表单、锁竞争为 409；未知故障为 500。不存在的私有目标与无权限目标使用不泄露存在性的拒绝结果。门户提供医院冻结的中文说明；若读取状态后发生停用，仍由写接口拒绝，页面提示刷新确认。状态 PUT 不接受名称、账号状态等额外更新字段。

## 7. 门户设计与降级

沿用现有 JSP 卡片、外部 CSS/JS、输出转义及导航，不增加前端框架或远程图表依赖。平台首页保留课程架构卡片，增加“医院管理”“跨院统计”“每日趋势”；医院首页增加“本院统计”。平台分医院表格不含患者、医生明细、预约/病历/账单 ID 或病历入口。

启停用普通 POST 门户表单转发 PaaS PUT，使用现有会话角色检查、CSRF 和提交后重定向。停用按钮附近持久显示“暂停预约、取消、接诊、缴费和资源维护，历史可查”，附带目标医院名及目标状态；不靠 JavaScript 确认弹窗才告知影响。启停后的重定向保留合法统计日期及医院列表页，不回显不安全输入。

统计筛选使用独立 `statsFrom/statsTo` 门户参数，再映射 API `from/to`，不与现有订单 `from/to/status` 筛选冲突。默认近 30 天，支持提交和重置；非法筛选保留转义输入和错误提示，不自动扩大到全时段。启停成功后刷新状态和统计，不在浏览器内修改数值冒充服务端结果。

每日趋势以可访问表格为完整信息载体，配本地 CSS 条形趋势辅助展示；零值正常显示，不以图代替精确数值。366 天表格允许纵向滚动，小屏在表格自身横向滚动，页面不整体溢出。无需 JS 即可筛选、启停和读取趋势；导航锚点、焦点样式及 `aria-current` 保持。

停用医院的医生/医院首页显示只读提示，写控件禁用或替换为说明，原历史区正常加载。各区独立读取：统计故障不清空订单/预约，医院列表故障不伪造统计为零，PaaS 不可用展示明确错误，不把异常结果当作零收入。授权失效只显示重新登录提示，不留下成功提交提示或旧私有数据。

## 8. 验证与验收

先测试后实现，并保留每轮 RED/GREEN 证据。至少覆盖：

1. 平台医院分页、仅合法状态、重复目标幂等、过期 `expectedStatus` 冲突，非平台角色不能读写管理接口。
2. 停用医院的启用医生/管理员可登录和读原有授权历史；缺失医院、未知状态、停用账号、旧令牌失效规则仍拒绝；重新启用不恢复独立停用账号/资源。
3. 逐个验证全部写入口在医院停用时失败且数据库业务行/状态/时间/金额不变；包括患者取消、支付及重复支付。停用前已开始但未完成的预约亦不能生成病历/账单。
4. 所有历史 GET 的本院/本人约束及跨角色/跨院拒绝；公共目录移除停用医院，历史仍可直接访问。
5. 至少两家医院、多状态预约、跨日诊疗/付款、零数据医院、零值日期、金额精度。验证群体状态合计、每日与区间合计、分院与平台合计。
6. 严格日期、闰日、单端缺省、倒置、366/367 天、上海午夜前后；选定范围与实际下单/完成/付款时间对应。改变测试 JVM 默认时区后仍验证显式上海日期换算；部署端配置须另外检查。
7. 旧 NULL 时间不被回填、不进入事件趋势；单列全量未知时间数量/金额，重付旧 PAID 订单不能伪造支付时间。
8. 响应字段白名单及查询投影检查，不包含个人身份、临床正文或私有记录 ID；统计不受现有 100/200 行列表上限影响。
9. 真 MySQL 使用两个事务验证“业务先持锁→停用等待”“停用先提交→业务拒绝”，覆盖预约、接诊、支付及资源维护代表入口，并检查统一锁顺序、回滚和无部分写入。H2 仅作快速回归。
10. 门户 CSRF、角色保护、输出转义、筛选隔离/保留、错误区独立、无 JS 表单，以及桌面/390px 小屏与趋势零值展示；回归目录级联、历史快捷入口和最后卡片导航。
