# 医疗云课程环境适配设计（待实施）

## 1. 依据与目标

本设计以教师提供的四份课件为课程验收依据。实验一课件第 9–10、19–20、42–43、116 页要求展示 IaaS/PaaS/SaaS 分层、JDK 8、Tomcat 9、WildFly 10、MySQL、SaaS Portal、PaaS 组件接口、JNDI/JPA 和 PowerDesigner 建模。C0 课件第 59、64–65 页把医疗云的预约挂号、疾病诊断、缴费列为课程项目场景，并将设计文档与个人实施列为重要评分项。C1+2 课件第 41、53–57、65、74 页强调 CloudServiceFactory、服务契约和 J2EE 分层。

目标是保留已有需求分析中的业务闭环与权限规则，使最终可演示系统能在教师实验环境的原工具链下构建、部署和访问；每一层都留有可核查的运行结果、接口与实验报告证据。

## 2. 当前架构的缺口

当前 `backend` 是 Java 21 + Spring Boot 3.4.5 的可执行 JAR，使用 Jakarta 命名空间和内嵌 Tomcat；`frontend` 是 Vue 3 静态资源，由 Nginx 托管。它可以完成业务演示，但不能在 JDK 8 下编译，也不能把现有 JAR 直接部署到 Tomcat 9 或 WildFly 10。Docker Compose 只能证明现代容器环境可运行，不能替代课程要求的两个 J2EE 中间件部署与 JNDI/JPA 实验。

因此课程交付以新的兼容实现为主；现有实现保留作业务规则、页面与回归测试的参考，不在原目录上直接降级依赖。

## 3. 目标结构

```text
浏览器
  │ HTTP
  ▼
Tomcat 9（SaaS Portal WAR，Java 8）
  │ 服务契约 / HTTP 调用
  ▼
WildFly 10（PaaS WAR/EJB，Java 8）
  │ JPA + JNDI DataSource
  ▼
MySQL（共享业务数据）
```

- SaaS：采用 Java 8 Web 工程、Servlet/JSP 门户，使用 `CloudServiceFactory`/门面按角色提供医院、医生、患者和监管视图；Portal 只处理展示与请求转发，不直接访问数据库。现有 Vue 页面可作为可选增强，但教师验收路径必须由 Tomcat 9 提供。
- PaaS：WildFly 10 托管业务组件，定义可检查的本地/远程服务接口及 REST 端点；业务边界为租户、账号、号源预约、接诊病历、订单支付与统计。服务端从认证上下文和数据库关系确定租户，维持现有权限约束。
- IaaS/数据资源：MySQL 通过 WildFly JNDI 数据源配置，JPA 管理实体和事务；文件可保留私有对象存储作为扩展，但不阻塞核心实验五。PowerDesigner 绘制应用场景、IaaS 部署、SaaS/PaaS 组件和数据模型，并提交可编辑源文件及导出图。
- 环境：课程主链使用 JDK 8、Tomcat 9、WildFly 10。当前机器已安装 JDK 8 和 MySQL 8.0.45，尚未检测到 Tomcat、WildFly、PowerDesigner。MySQL 版本以课程现场可用版本为准，SQL 脚本避免依赖 8.0 特有能力。

## 4. 业务与接口

第一条必须完成的链路是医院/医生资料 → 发布号源 → 患者预约 → 医生接诊并记录诊断 → 生成账单 → 患者模拟缴费。对外契约包含身份、所属机构、请求/响应、错误码和授权角色；至少演示一次跨租户拒绝及一次重复预约拒绝。监管视图只能获取脱敏汇总。原系统的附件、审计和细粒度管理能力在课程主链稳定后逐项迁移。

SaaS 到 PaaS 的接口采用清晰的 HTTP/JSON 契约；WildFly 内部通过 EJB/JPA 组件组织业务，实验四展示本地/远程接口定义与调用，实验五展示 JNDI/JPA 的真实读写。需要对错误响应、超时、事务与权限进行集成测试。

## 5. 交付和验收证据

1. 环境：`java`、`javac` 显示 1.8；Tomcat 9 在教师要求的 8088 端口启动；WildFly 10 和 MySQL 可用。
2. 建模：PowerDesigner 的源模型、导出图与模型说明覆盖 IaaS/PaaS/SaaS、服务接口、数据实体。
3. 部署：SaaS WAR 在 Tomcat 9、PaaS 组件在 WildFly 10；浏览器入口可访问，服务调用链可追踪。
4. 业务：全新演示数据可走通预约、接诊、缴费；权限边界测试通过。
5. 报告：实验 1–5 对应步骤、环境截图、接口调用、数据库持久化、AI 分析与人工差异审查，以及最终演示脚本。

## 6. 实施顺序

先完成 Java 8 兼容的最小纵向切片和两个容器间的真实调用，再移植其余业务。随后补建模源文件、部署自动化和实验报告证据。现有 Java 21 系统保留在独立开发分支，避免课程适配破坏已实现功能；课程验收通过后再决定是否保留双部署方案。

## 7. 风险与裁决

- Spring Boot 3/Jakarta 与 JDK 8/WildFly 10 的代际冲突意味着需要重建兼容模块，不能通过改 Java 版本号解决。
- 课件中的 MySQL 5.6 属实验示例，当前本机是 8.0.45；本方案保持 SQL 兼容并在实际使用版本上验证，若教师明确要求 5.6 再加该版本的容器或虚拟机验证。
- PowerDesigner、Tomcat 9、WildFly 10 当前不在已检测位置；缺少工具时先实现和编译模块，真实部署结论只能在安装并运行后给出。
