## 1 目标和范围

为期末医疗云演示补齐两条附件链路：患者向本人预约上传脱敏检查资料，接诊医生查看资料；医生向本人已完成病历追加演示附件，患者查看本人病历附件。全部使用虚构或脱敏的 JPG、PNG、PDF，不接入真实医疗信息。

沿用老师要求的 Java 8 → Tomcat 9 Servlet/JSP → WildFly 10 JAX-RS/EJB → JPA/JNDI → MySQL 主链。MinIO 提供私有对象存储，数据库保存元数据，不保存文件二进制或永久公开链接。上传、授权签发、删除和失败补偿接入已有脱敏审计。

本阶段交付课程契约、数据库增量迁移、PaaS 服务、患者/医生门户、存储配置、安全与一致性测试、独立实机验收及演示说明。功能完成必须同时覆盖两类附件，不能用医生病历上传替代患者预约上传，也不能只验证模拟存储就宣称真实 MinIO 验收通过。

不包含病情补充、病历草稿/更正、药品处方、医院新建/管理员开通、订单取消、评价、AI、真实支付、杀毒产品、DICOM、跨区域灾备或生产医疗合规。这些排除只限定本切片，不删除完整范围清单中的后续任务及冲突。今后不制作 PowerDesigner 图；现有图件、需求书和历史证据保留不动。70 台 IaaS 仍仅是模型，不实际启动。

## 2 需求依据和方案选择

业务依据是仓库需求分析说明书 V1.0 的 FR-FILE-01～04、UC-03、UC-05、FR-TEN-05、NFR-03/04 和 AT-06；补充依据是 9 月 13 日完整系统设计第 4.5 节及 10 月 4 日完整范围核对。技术路线以较新的课程环境和审计设计为准，不恢复 Spring/Vue 路线。

患者上传的用例条件为“尚未完成接诊”，因此允许 `BOOKED` 和 `IN_PROGRESS`，不是仅限接诊前。误传文件删除则仅允许接诊开始前。课程现有取消状态拼写为 `CANCELED`，不为附件阶段改写旧业务状态。

选择私有 MinIO 与数据库持久化操作状态的方案。相比本地私有磁盘，它符合已确认的对象存储路线，能在两台 Web 容器与独立存储之间展示云服务接口。相比浏览器直传对象存储，PaaS 接收文件并校验更容易收住患者、预约、类型和状态边界，不向浏览器提供上传存储凭据，也不把患者自行报告的校验结果当作证据。

MinIO 不参加 JTA。采用短数据库事务与存储操作分离的补偿流程，不在数据库锁内等待大文件网络传输，不声称具备跨 MySQL/MinIO 原子事务。核心预约、接诊、病历提交与缴费不得等待 MinIO；存储不可用时只降级附件操作。

## 3 组件和接口边界

- `course/contract` 定义附件元数据、分页、上传准备、操作状态和下载授权 DTO；不会向普通列表输出 bucket、object_key、存储地址或凭据。
- PaaS `AttachmentResource` 负责认证、参数、状态码、限流入口和请求关联；`AttachmentCoordinator` 为不参与事务的编排边界；数据库 EJB 分别完成准备、认领、发布、逻辑删除和补偿状态更新。
- `AttachmentAccessPolicy` 在已有 `TenantAccessPolicy` 上校验账号、角色、资源所有者和跨表租户关系；不能仅凭角色门面、URL 中的医院 ID 或上传 ID 授权。
- `PrivateObjectStore` 封装上传、对象校验、五分钟 GET 签名、删除和受控枚举。只有 PaaS 持有存储应用凭据；不向 SaaS 暴露 MinIO SDK。
- `AttachmentValidator` 对有界临时文件进行真实格式解析和 SHA-256 校验，不把扩展名或 Content-Type 当作真实文件格式。
- `AttachmentReconciler` 用 EJB 定时任务处理失效上传和待删对象；默认单课程实例执行，不引入消息队列。数据库条件更新和行锁保证重入安全。
- Portal 新增独立 `AttachmentWorkspace`/Servlet 和 JSP 区域，避免继续把大文件处理堆入 `PortalServlet`。保留服务工厂与角色门面，将附件动作加入患者和医生门面；门面只改善交互，PaaS 授权仍是最终边界。

门户接受标准 Servlet multipart 表单；PaaS 使用 JSON 准备请求加原始二进制内容请求，不添加与 WildFly 自带 RESTEasy 版本冲突的 multipart 提供者。Portal 的 `PaasClient` 增加独立有界二进制转发入口，不把文件编码进 JSON，也不提高已有 1 MB JSON 响应上限来容纳二进制。

## 4 附件归属和权限

每个文件属于一个预约，租户、患者、接诊医生均从预约及关联病历取值。`source_type` 为 `PATIENT_APPOINTMENT` 或 `DOCTOR_RECORD`；后者必须关联一个实际存在且属于该预约的病历。两类文件不能由客户端互相改型或重新绑定。

| 动作 | 患者预约附件 | 医生病历附件 |
| --- | --- | --- |
| 新建和上传 | 当前启用患者的本人预约；医院启用；预约为 BOOKED/IN_PROGRESS | 当前启用医生本人本院的已完成病历；医院启用；预约为 COMPLETED |
| 列表和签发下载 | 本人患者；分配给该预约的本人本院医生 | 本人患者；原接诊医生本人本院 |
| 用户删除 | 仅原上传患者；医院启用；预约仍为 BOOKED 且 started_at 为空 | 不提供用户删除或覆盖，使用追加附件保留原记录 |
| 管理员 | 医院及平台管理员无内容、文件名、对象键或签名地址访问权 | 相同 |

患者是平台账号，不能要求其账号 `tenant_id` 与医院一致；但文件的租户必须与预约一致。医生必须同时满足账号角色、账号医院、预约接诊医生和病历归属。不存在和无权访问的资源统一拒绝，不泄露其他患者的文件是否存在。

医院停用后禁止上传、准备新上传和用户删除，但启用账号仍可按上述归属查询历史并申请下载。账号停用或令牌过期后不签发新链接。已取消预约的历史附件仍可由本人患者与原分配医生查询，不允许新上传或恢复已删文件。

医生病历附件在病历创建后追加，患者立即可查看；不改写原病历内容或完成时间，不重新生成订单。旧病历时间为空不代表文件无权读取；仍以现有病历、预约和身份关联授权，不补造旧时间。

## 5 文件验证和资源限制

默认最大文件长度为 `10 * 1024 * 1024` 字节。配置为正整数字节，默认 10 MiB；门户统一标注“10 MB（10,485,760 字节）”，避免边界解释不同。部署可调整，但 Portal 和 PaaS 必须使用一致值。超限、空文件、长度不符及 SHA-256 不符均拒绝。

允许 `.jpg`/`.jpeg`、`.png`、`.pdf`，声明 MIME 必须对应 JPEG、PNG 或 PDF；最终存储 MIME 由服务端验证结果确定。原文件名去除路径部分，拒绝控制字符、CR/LF 和空名，限制为 255 UTF-8 字节；显示时 HTML 转义，不能参与存储路径、日志文本或 HTTP 头拼接。

JPEG/PNG 必须满足格式签名并能完成标准图像解码；先检查尺寸，默认最多 20,000,000 像素，防止小文件引起无界解压。PDF 必须能解析为至少一页，默认不超过 200 页；拒绝加密、嵌入文件、JavaScript、启动动作和自动打开动作，遍历动作关联使用去重和有界深度，不只查文档根节点。不执行 PDF 内容，不在页面内直接嵌入 PDF。页数、像素限制均是可配置的演示资源保护，不支持 DICOM 或其他格式。

文件以随机生成的临时名称保存在隔离、非 Web 根目录，Portal 和 PaaS 都按流计数限制长度；PaaS 再次校验真实内容与摘要。临时文件只用于验证/转发，不作为永久存储。请求结束在 finally 清理自己创建的精确临时文件；失败清理使用白名单目录和文件归属核对，不递归删除用户目录。

默认每个容器最多四个并行文件处理请求，每个上传者最多两个未结束上传；可配置。配额满时返回 429，避免无限创建上传准备记录或临时文件。限制检查必须支持并发，不能采用“先数后无锁插入”。存储连接超时默认 3 秒、单次存储调用总时限 90 秒，内容接收总时限 120 秒；容器同时配置有限读等待和请求体上限，不能只靠 Content-Length。

这是格式和资源校验，不是杀毒保证。只允许虚构/脱敏文件，下载以附件形式返回，浏览器不把它当同源 HTML 执行；图片和 PDF 合法也不能据此保证不存在恶意内容。

## 6 持久化结构和状态

新增 `file_metadata`，兼作上传意图和清理清单，数据库实体显式登记到 `persistence.xml`。同一行的 id 即上传操作 uploadId 与发布后的 fileId，不另造无法追踪的临时业务 ID。结构字段如下：

- `id`、`tenant_id`、`appointment_id`、`patient_id`、`doctor_id`、`uploader_id`，均为 36 字符标量 ID。
- `record_id` 可空；患者预约附件为空，医生附件非空；`source_type` 明确区分二者。
- `file_name`、`content_type`、`size_bytes`、`sha256`，分别为安全展示名、受限 MIME、BIGINT 和 64 字符十六进制摘要。
- `object_key` 为服务端生成、不超过 128 字符的 ASCII 键，例如 `course-attachments/<file_uuid>/<random_uuid>`，不使用姓名、文件名、病情或请求提供的路径。
- `upload_key` 为上传者提供的规范 UUID 幂等键；唯一约束 `(uploader_id, upload_key)`；`object_key` 独立唯一。
- `state`、`created_at`、`updated_at`、`lease_until`、`deleted_at`、`attempt_token`、`retry_count`、`next_retry_at` 和 `version`，支持状态机、并发认领和补偿。

使用 InnoDB、utf8mb4 和版本化 SQL，按 MySQL 5.6 语法设计，不依赖其不执行的 CHECK 约束、JSON 字段或 8.0 特有索引。业务状态、空值组合及跨表租户一致性由服务校验和数据库测试证明。引用外键不使用删除级联；新表新增关联不反向改写原九表内容。

索引覆盖 `(appointment_id, source_type, state, created_at, id)`、`(tenant_id, state)`、`(state, next_retry_at, id)`、`(state, lease_until, id)` 和上述唯一约束；键长度明确按目标字符集核算。普通列表不返回内部上传租约、尝试令牌、对象键或清理字段。

状态为 `RESERVED`（已准备、无有效文件）、`UPLOADING`（被一个请求认领）、`AVAILABLE`（可授权读取）、`DELETE_PENDING`（已逻辑删除、待物理清理）、`DELETED`（已确认物理不存在）、`ABORTED`（上传放弃、禁止发布）。客户端不能直接设状态。

仅 `AVAILABLE` 能列入业务文件列表或签发下载地址。上传失败的意图/墓碑不等于有效元数据，不出现在医生接诊资料中。元数据墓碑保留用于重试与对账，不提供恢复、覆盖或用户物理删除接口。

## 7 上传一致性和重试

### 7.1 准备与接收

Portal 先接收一个有界临时文件，计算 SHA-256；经服务端会话令牌向 PaaS 准备上传，提交文件名、MIME、实际大小、摘要和上传幂等键。直接 API 调用者可自行声明同样字段，但内容请求必须由 PaaS 重新验证。

准备 EJB 在短事务中核验归属、医院可写、预约状态和并发配额，再插入 `RESERVED`。初始有效期为 15 分钟。相同上传者/幂等键及相同目标、文件描述返回原操作；任何字段不同返回 409，不新建另一文件。准备失败不写对象。

内容入口再次认证，短事务以行锁将 `RESERVED` 认领为 `UPLOADING`，生成内部 `attempt_token`，租约为 10 分钟。其他内容请求不得同时写该对象；活跃上传返回 409。接收、解析和 MinIO 上传均在无 JTA 的编排边界中进行，使用有界临时文件和已生成的对象键。

相同操作已 `AVAILABLE` 的重试只返回同一文件元数据，不再次写对象；幂等键已在准备阶段绑定实际摘要。客户端若换文件必须换幂等键并重新准备。`ABORTED`、`DELETE_PENDING` 或 `DELETED` 不可重启上传。

### 7.2 发布和临床并发

对象上传成功后，发布 EJB 重新核验账号启用、医院启用、预约/病历归属、内容摘要以及当前尝试令牌和未过期租约。患者预约状态仍须为 BOOKED/IN_PROGRESS；医生病历须仍存在且关系一致。完成 `UPLOADING → AVAILABLE` 与 `FILE_UPLOAD` 成功审计在同一事务提交。

临床并发以预约锁为共同串行化点。附件的准备、发布和逻辑删除沿用已有相关锁顺序：医院 → 接诊医生账号 → 上传者账号（若与医生相同只锁一次）→ 号源 → 预约 → 附件；不持有附件锁后再反向获取临床锁。上传者账号锁同时保护跨预约的未结束上传配额，不能先数后插入。租户状态切换与相关业务写入共享医院锁。每个事务刷新后重新核验，不依赖先前读取的 JPA 快照或前端按钮状态。

若发布先提交，后续完成接诊能看到该附件；若完成接诊先提交，患者发布被拒绝并补偿清理对象。删除与开始接诊亦如此：删除先提交则附件已退出可用集合，开始接诊先提交则患者不能删除。此阶段不让接诊 start/complete 依赖存储调用或附件任务成功。

### 7.3 失败、未知提交和迟到写入

格式/大小/摘要错误、存储失败、发布校验失败或数据库回滚都不得产生有效文件。已提交的意图保留；编排器使用新的短事务在当前尝试仍匹配时将其标为 `ABORTED`，然后对该键执行补偿删除。若更新状态失败，原 UPLOADING 意图由过期租约回收。

数据库提交响应丢失时不能猜测失败并直接删对象。先在新事务读取状态：AVAILABLE 则保留，已终止则补偿；数据库不可读时只报告结果待确认并交由后续查询/回收。不得因“客户端收到 500”删除实际已提交的文件。

回收器过期认领 RESERVED/UPLOADING 时，先以条件更新提交 ABORTED，再删除对象；迟到发布因状态/尝试令牌检查失败，绝不能使 ABORTED 复活。清理持久墓碑和受控桶前缀时重复确认对象，处理迟到存储 PUT；不能因一次 HEAD 不存在就永久忘记墓碑。所有本应用对象写入前必须有已提交意图，所以正常失败对象均有持久清理依据。枚举时只清理能由对应终止意图证明归属的键；未登记对象生成仅含数量和安全故障类型的复核提示，不擅自删除，也不把这种异常写成“零残留”。

普通时限内后台任务最多每分钟执行一次，每批最多 100 条；失败按 1/2/4/8/16/30 分钟退避，之后保持 30 分钟，不无限占用线程。已清理的 ABORTED/DELETED 墓碑也每 30 分钟安排下一次存在性核对，成功只重置失败次数，不永久退出扫描。对象迟到或清理失败可暂留私有字节，但不成为可签发资源；存储恢复后继续收敛。进程崩溃、服务重启和清理错误不会丢失待处理清单。

## 8 删除和下载

用户删除先在短事务中锁定并核验本人患者、有效医院、BOOKED 且 started_at 为空，将 AVAILABLE 改为 DELETE_PENDING，写入删除时点和 `FILE_DELETE` 成功审计。这是逻辑删除被受理的事实，不等于已经物理销毁。随后才在无 JTA 边界执行对象删除；确认不存在后短事务改为 DELETED。

物理删除失败仍保持不可列出/不可新签发，返回 202 和 `DELETE_PENDING`，门户显示“已移出资料，存储清理待重试”；不能误报永久清除。已物理删除返回 200。相同上传者重复请求已删文件返回原状态并写 `NO_CHANGE`，不重新触发临床状态转换；其他人仍拒绝。并发删除只发生一次有效逻辑转换。

下载入口先验证有效账号和资源归属，确认 AVAILABLE，对象存在后生成 300 秒有效的 GET 签名。使用浏览器可访问的专用存储端点签名，不能签完再替换 hostname。bucket 禁止匿名读/列举；文件名只用于经过编码的 attachment Content-Disposition，不提供永久链接或可执行内联页面。

签发 EJB 在同一事务中再次校验账号/归属，按父资源在前、附件在后的顺序取得短期读锁，核验文件仍 AVAILABLE 并写 `FILE_DOWNLOAD_AUTHORIZE` 审计；只有提交成功后向客户端返回 URL。签名生成和对象可用性探测在数据库事务外完成，签发提交前重新检查文件状态/版本，不能只读取版本却不锁定就声称阻止了并发删除。审计失败不返回链接。成功响应包含 `fileId/url/expiresAt` 并设置 `Cache-Control: no-store`，不加入普通列表。expiresAt 是签名生成时刻加 300 秒，不因事务等待或页面重试延长；两端时钟需同步。

签名 GET 是持有者凭证。链接在签发后可能被转发，在 300 秒内不再次检查平台账号；账号停用不能立即撤销已签发 URL，逻辑删除也可能要等对象实际删除或 URL 到期。该限制在门户提示和部署说明中披露，不宣称按人实时撤销。匿名仅凭 object_key 不能读取；验收测试要分别验证“未签名拒绝”和“已签名持有者可读”。审计记录的是授权签发，不是浏览器已实际下载完毕。

## 9 PaaS 和门户契约

路径均相对于现有 `/paas/api`，响应沿用 `ApiResponse`/`ApiError`。普通元数据包含 fileId、sourceType、安全文件名、实际 MIME/大小和创建时间；操作查询另含 state，不含内部清理参数。

| 方法和路径 | 内容 | 授权及幂等要求 |
| --- | --- | --- |
| GET `/patient/appointments/{id}/files?page=1&pageSize=20` | 本人预约的两类可用文件，稳定按 created_at/id 排序；页长 1～100 | 本人患者，先授权父资源；返回分页总数 |
| GET `/doctor/appointments/{id}/files?page=1&pageSize=20` | 本人本院预约的两类可用文件 | 分配医生，同上 |
| POST `/patient/appointments/{id}/files/uploads` | JSON 准备患者附件 | 本人患者、医院可写、BOOKED/IN_PROGRESS；上传 UUID 幂等键 |
| POST `/doctor/records/{id}/files/uploads` | JSON 准备医生附件 | 本人本院已完成病历；上传 UUID 幂等键 |
| PUT `/files/uploads/{uploadId}/content` | 原始 application/octet-stream | 仅该操作原上传者；有界读、真实验证与条件发布 |
| GET `/files/uploads/{uploadId}` | 自己上传操作的状态和结果 | 仅原上传者；中断后按 ID 查询，不依赖截断列表 |
| POST `/patient/files/{fileId}/delete` | 接受逻辑删除并尝试物理清理 | 原上传患者；状态/归属规则见第 8 节 |
| POST `/files/{fileId}/download-url` | 单次签发五分钟链接 | 本人患者/分配医生；每次重新授权、不得缓存为列表 |

page/pageSize 坏值返回 400；列表先验证身份与父资源，不用参数解析优先泄露受保护信息。按页读取要求在同一数据库视图完成总数和列表，空页可导航，不用固定截断代替分页。

新增稳定错误：400 `FILE_INVALID`/`UPLOAD_DESCRIPTOR_INVALID`，413 `FILE_TOO_LARGE`，415 `FILE_TYPE_UNSUPPORTED`，409 `UPLOAD_IN_PROGRESS`/`UPLOAD_CONFLICT`/`FILE_STATE_CONFLICT`，429 `FILE_LIMIT_REACHED`，503 `OBJECT_STORE_UNAVAILABLE`；保留 401/403 和安全 500。统一返回服务端 requestId，不输出异常正文、文件字节、URL、object_key 或原始请求。现有 JSON-only 415 文案必须仅影响 JSON 入口，不能错误套用到二进制上传。

门户在患者预约详情展示上传、分页列表、删除和下载；在医生预约详情展示患者资料，在医生已完成病历区域展示追加附件和下载。提供大小/类型说明、处理中、空状态、存储不可用、待清理、租户冻结与权限提示。病历没完成时不显示医生病历附件上传按钮，但患者资料仍能查看。

Portal 所有写动作和下载签发使用 POST 加现有 session CSRF token，multipart 同样校验。认证/角色在接收前检查，解析阶段仍执行容器限额；字段白名单，不转发浏览器 Authorization、tenant_id、patient_id、doctor_id 或自定义目标 URL。门户只用服务端 session 保存的用户令牌调用 PaaS；直接 API 仍接受有效 Bearer 令牌并执行同样的后端授权。

保留上传 UUID 和操作 ID，超时提示“结果待确认”并可按 ID 恢复，不自动创建另一个上传。普通上传/删除表单支持禁 JavaScript 的浏览器，采用正常提交和 PRG；下载签发 POST 直接呈现一次性的授权页面，不重新签发以实现重定向。页面有明确有效期与安全点击链接，不把签名 URL 放进重定向 Location、会话 flash、localStorage 或审计。该页面 no-store、Referrer-Policy no-referrer，链接不预取；Portal 验证返回 URL 是配置允许来源的 HTTP(S) 地址且做 HTML 属性转义，不让浏览器带同源来源信息给存储。

## 10 审计和隐私

新增 `FILE_UPLOAD`、`FILE_DELETE`、`FILE_DOWNLOAD_AUTHORIZE` 三种事件及 `FILE_METADATA` 对象类型，医院/平台的事件筛选白名单和标签同步更新。沿用既有成功事务内写入、失败独立事务和请求关联规则，失败审计故障只输出安全 requestId 与白名单类型。

不改变现有 AuditOperationRunner 的单业务 EJB 调用约束。附件编排器在每个数据库 EJB 代理已返回、事务已结束后才协调独立失败审计；已确认 AVAILABLE 或逻辑删除提交成功后发生的响应展示/物理清理错误，不能再追加同请求的业务 FAILURE。数据库提交结果未知时先查状态，不猜测审计结果。

只记录可信账号/医院标量关联、文件 ID、动作、结果、原因和时间；管理端仍不返回 actor_id/object_id，不提供临床附件下钻。禁止保存文件名、摘要、MIME 细节、存储键/端点、大小明细、签名 URL、内容、凭据或异常链。新错误原因使用封闭枚举，不增加自由文本审计字段。

复用现有封闭原因：400/413/415 文件输入错误记 BAD_REQUEST，409/429 记 CONFLICT，503 存储故障和审计故障记 INTERNAL_ERROR；401/403 分别记 UNAUTHORIZED/FORBIDDEN，首次成功为 OK，重复已完成操作为 UNCHANGED。对外细分文件错误码，但不把自由文本或存储异常加入审计原因。

准备操作不是上传成功；FILE_UPLOAD SUCCESS 仅对应发布 AVAILABLE。失败内容请求记录 FAILURE；同一文件重试成功不产生第二次有效发布，实际重试请求可以追加 NO_CHANGE。删除成功对应移出资料，物理清理状态另由内部状态表证明；定时清理不是患者再次删除，不伪装成人类操作。

文件授权签发成功日志和元数据状态可以证明许可流程，不能证明真实诊疗使用、实际下载完成或病毒扫描。管理端审计正文、门户通知与容器访问日志均不得落入完整签名查询串。

## 11 配置和部署安全

PaaS 从环境配置读取存储启用、内部 S3 端点、外部签名端点、区域、bucket、应用 access/secret、大小/格式资源限制和临时目录。Portal 只读取相同文件大小限额、允许的下载来源、自己的临时目录和现有 PaaS URL，不接触存储 secret。格式不合法的配置应在附件模块报告不可用，不能阻止核心 WAR 提供诊疗流程。

签名端点来自受控部署配置，仅允许 HTTP(S)，禁止 userinfo、查询/fragment 和从用户请求指定端点；客户端不能指定任意 bucket 或 object_key。开发/验收仅使用 loopback 独立实例；非本机部署必须使用 HTTPS，不能把 HTTP 本机证据写成云端传输安全已验证。

MinIO 使用本阶段专用私有 bucket，启用最小权限应用账号，仅允许相应前缀的 PUT/GET/HEAD/DELETE/LIST，不使用 root 账号运行应用。bucket 建立和匿名策略核对由显式部署步骤完成，PaaS 不自动修改已有 bucket 策略。禁用版本保留与对象锁的专用演示桶用于本删除流程；部署预检发现不匹配时拒绝操作，避免 delete marker 被误说成物理删除。

默认部署实例完成启动后可观察“附件可用/不可用”，核心健康检查不依赖 MinIO。附件验收必须显式启用并证明真实存储操作，不能用关闭模块的核心健康检查当完整启动通过。

SDK 候选沿用现有仓库 MinIO 8.5.17；PDF 采用 Java 8 可用的 PDFBox 2 系列。实施计划先锁定具体依赖并核验维护/已知安全问题、Java 8 字节码及 WildFly 10 类加载；不把旧 Java 21 构建当兼容证明。若候选有不兼容或严重安全问题，选同架构兼容补丁并记录理由；不得为省事升级 JDK/容器或改用 Spring。WAR 保留容器提供的 Java EE/RESTEasy，不把 SDK 依赖的 JSON 库污染已有共享契约。

新空库同步 schema；已有审计版库使用独立 `003_attachments.sql` 和保护性升级器。先只读核对明确主机/端口/数据库/服务器 UUID、原九表完整结构及新表是否存在；正确新表已存在时报告已升级并停止，残缺/异构新表拒绝。全库备份成功才 DDL，不重跑 seed、不更新旧业务行，不自动部署 WAR。

MySQL DDL 可能部分提交；失败后报告实际结构，不盲目重跑、DROP 或覆盖恢复运行库。本轮在新建 disposable 数据库与独立双容器/MinIO 中验证。原 `task8-runtime-20260928`、3318/8180/8188/10090、教师安装与共享 MinIO 不升级不重启。实机迁移/部署到任何已有运行库前另行确认精确目标和维护窗口。备份、夹具、存储凭据和签名响应证据只存 Git 忽略目录。

## 12 验收标准和证据

实施遵循先失败测试后实现。每一门保留实际执行项、失败/跳过数和环境，不把源码搜索、结构测试、模拟适配器或历史审计结果当作新鲜附件实机验收。

1. 两类 JPG/PNG/PDF 上传与分页/按 ID 恢复；10 MiB 边界、限额修改、空文件、超限、伪造 MIME/后缀、损坏文件、摘要错误、图片解压限制及 PDF 受限内容均有正负测试。
2. 四角色、双医院、两个患者、同院非分配医生矩阵，覆盖准备/内容/状态/列表/删除/下载；替换 fileId/uploadId/appointmentId/recordId 或构造跨租户关联不能泄露有效元数据与字节。
3. 患者接诊中仍能上传，已完成/已取消拒绝；开始与删除、完成与发布、医院停用与发布的真实数据库并发测试证明锁和状态规则。医生只能追加本人已完成病历；原病历、订单不变。
4. 私有桶匿名 GET/LIST 和仅对象键读取拒绝；授权链接可读正确内容，签名篡改与到期拒绝；300 秒实际有效期及浏览器可达端点有证据。披露已签 URL 的持有者语义。
5. 上传键重试、并发认领、响应丢失、提交结果未知、对象已写后数据库失败/审计失败、进程重启、过期回收、迟到 PUT、逻辑删除后物理失败及重试，都不出现不可追踪有效对象或被误删的 AVAILABLE 文件。MinIO 与数据库摘要/状态双边核对，不能仅靠 HTTP 200。
6. 新迁移、只读重复执行、基线错配/部分新表/失败备份拒绝、旧行摘要不变、外键/索引/JPA validate，真实 disposable MySQL 验证；可用 8.0 实测必须披露 5.6/教师机器未验，不伪造兼容证据。
7. 真实 JDK 8/Tomcat 9/WildFly 10 部署与 SDK、事务边界、独立失败审计；管理端新事件分页/筛选脱敏，敏感值不进入日志/列表/页面源码的非授权区域。记录库和安全日志证明不含文件正文、存储键或签名地址。
8. 最新 Chrome、Edge 的患者/医生上传、删除、下载、键盘和常见笔记本布局；禁 JS 表单、未登录/过期/403、存储 503、413/415/429、上传超时、结果恢复、医院冻结与历史只读有实际观察。浏览器只用虚构文件，不在截图中暴露链接签名、令牌或密码。
9. 新独立环境按说明从零配置、初始化私有桶、迁移和启动，运行完整演示；停 MinIO/故障注入时核心预约→接诊→订单→模拟支付仍能完成。停止验收只关闭精确实例并保留证据，不全局强杀或清理用户数据。

阶段报告区分“已实现”“单元通过”“真实数据库/对象存储/容器通过”“浏览器已观察”与未验证项。附件完成后再次停下来汇报，再推进完整范围清单下一部分；此阶段验收不替代全系统性能、备份恢复、云端部署、最终报告/PPT或未完成业务。
