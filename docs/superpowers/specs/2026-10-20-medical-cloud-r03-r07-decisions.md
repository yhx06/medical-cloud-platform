# R03–R07 范围裁决记录（2026-10-20）

状态：用户已在对话中逐项选择。本文只记录已确认范围，不代替各切片的详细实施计划；未列出的行为不得自行扩大。

## 1. R04 预约时间冲突

**已确认规则：同一患者、跨医院/跨医生、半开区间重叠即拒绝。**

- 参与冲突的预约状态：`BOOKED`、`IN_PROGRESS`；`CANCELED`、`COMPLETED` 不占用未来时段。
- 区间为 `[start, end)`：新预约 `start < 既有 end` 且 `既有 start < 新 end` 才冲突；端点相接（前一结束 = 后一开始）允许。
- 时区固定 `Asia/Shanghai`；号源日期与起止时间来自 `schedule_slot`，不跨日。
- 取消后释放该时段；容量与同号源重复预约规则不变。
- 并发：以患者账号行为串行化锁，锁内查询该患者所有有效预约的重叠；不能只依赖同号源唯一约束。
- API 冲突使用稳定业务码 `APPOINTMENT_CONFLICT`（409）；门户保留当前筛选/号源列表并显示中文提示。
- 不新增表；需要为 `appointment(patient_id,status)` 或等价查询补充索引，迁移编号按届时 schema 顺序分配。

## 2. R05 未支付订单取消与支付流水

**已确认：不实现订单取消；只补唯一支付流水。**

- 保留“完成接诊后订单不可取消、原病历不可更正修改”的既有规则；不新增 `CANCELED` 订单状态、不撤销接诊、不回退预约。
- 支付仍为模拟支付，不接真实资金服务。
- 每笔订单首次支付时在同一事务生成唯一支付流水号；重试/重复支付保持原流水号与原 `paid_at`；不同订单不碰撞。
- 建议格式：`PAY-YYYYMMDD-<12 位大写十六进制>`，服务端生成，数据库唯一约束；具体格式在详细设计中固定。
- 旧 `PAID` 行在保护迁移中生成一次性流水并保持金额/时间/病历不变；`UNPAID` 行流水为空。
- 查询/门户只显示脱敏流水号，不显示内部密钥或支付凭证。

## 4. R03 医院/医生/本人资料

**已确认：最小可写资料，不做资质认证与公开目录。**

- 医院名称：医院管理员可修改本院名称；平台管理员只读展示；修改需服务端授权、长度 1–100、控制字符/非法代理拒绝、HTML 转义、审计。
- 医生资料：医生本人可修改自己的职称（`title`，≤100）与简介（`bio`，≤1000）；医院管理员只读查看本院医生资料；其他角色不可写。
- 患者资料不新增可写字段；平台不新增资料审核/通知。
- 不做真实资质文件、证书上传、公开医生目录或跨院资料编辑。
- 需要保护迁移新增医生职称/简介列；医院名称复用 `tenant.name`，不新增列。
- 所有写入口重新认证、校验角色/租户/对象归属，失败返回安全错误；门户使用原生表单、label、中文转义与 CSRF。
